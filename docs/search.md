# 搜索与推荐 2.0（L26 · 1.26.0）

## 搜索页 `/search/`

- **联合搜索**：一个输入框同时搜 **文章、作品、影集、创作者、话题**。结果按类型标出（文 / 图 / 集 / 人 / #），命中的词高亮。
- **筛选**：类型（全部 / 文章 / 作品 / 影集 / 用户 / 话题，每个后面显示命中数）、标签、年份；点「结果里的标签」也能直接按标签筛。
  所有条件都写进网址：`/search/?q=夜景&type=work&tag=街头&year=2026`，可以收藏或分享；非法参数会被忽略。
- **没有结果时**：给出相近的标签 / 标题（字符二元组相似度），有筛选时提示「清除筛选」。
- 数据来源各自独立：文章（`/api/search-index`）、作品（`/api/content/works`）、影集（`/api/content/gallery`）、创作者与话题（`/api/social/discover`）。
  某一类加载失败只跳过那一类，并在状态里说明。

## 排名（`web/src/search-core.ts`，Worker 里是同一份文件）

- **切词**：先做 NFKC 归一和小写；英文 / 数字按词，中文按 **二元组**（「城市夜景」→ 城市 / 市夜 / 夜景），单字保留。
- **匹配**：查询按空格 / 标点切成片段，每个片段都要命中（AND）。英文词必须出现；中文片段命中 **≥ 60%** 的二元组就算命中，
  所以「城市夜景」也能找到正文写「城市的灯光」、标签是「夜景」的文章。
- **打分**：字段加权 BM25（标题 3 · 标签 / 分类 / 系列 2 · 摘要 1.2 · 正文 1）；标题完整包含查询再 +2，标签等于查询 +1.5。
- **去重与多样性**：按「类型:id」去重；前 5 名里同一系列最多 2 条，多出来的顺延（不丢）。
- 单元测试 `web/test/search.test.ts` 用一份固定的虚构语料，写死每个查询的前 3 名，改排名必须同时改测试。

## ⌘K 命令面板

- 文章条目和搜索页用同一套排名：search-core 的命中与原来的模糊匹配合并（同一篇取较高分），所以只在正文 / 标签里出现的词也能在 ⌘K 里找到文章。
- 面板底部「在搜索页全文搜索」直接带上关键词。

## 相关推荐

- 文章末尾的「相关推荐」：标签 Jaccard ×3 + 同分类 +1（同系列的文章已经在系列导航里，默认排除），零分不推荐；
  再做 **MMR 多样性重排**（λ = 0.7：既要相关，又不要和已选的太像），同一系列最多 2 篇。

## 接口 `GET /api/search?q=&tag=&year=`

- Worker 与演示站 mock 都有：只搜已发布文章，返回 `{ hits: [{ slug, title, summary, tags, category, series, publishedAt, score }], total, suggestions }`。
  查询超过 80 字会被截断；空查询返回空结果。

## 没有做的（SKIPPED-verifiable）

- **D1 FTS5 全文索引 + 触发器**：需要真实的 Cloudflare D1 部署才能验证；目前 Worker 接口在内存里建索引（文章量在几千篇以内足够），演示站用浏览器内索引。
- **语义搜索（Workers AI 向量）**：需要 Workers AI，未实现、默认关闭。
